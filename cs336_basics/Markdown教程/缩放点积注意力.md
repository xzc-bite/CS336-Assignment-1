## 1. 一句话理解与名字拆解

### 1.1 公式

缩放点积注意力的定义是：

$$
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

其中：

- $Q$：Query，查询；
- $K$：Key，键；
- $V$：Value，值；
- $d_k$：每个 query/key 向量的维度，也就是**每个头的维度**；
- $\operatorname{softmax}$ 沿着“key 的维度”做归一化。

### 1.2 名字里的三个词

| 名字 | 含义 | 对应公式 |
| --- | --- | --- |
| **Dot-Product**（点积） | 用点积衡量 query 和 key 的相似度 | $QK^\top$ |
| **Scaled**（缩放） | 把点积除以 $\sqrt{d_k}$，控制数值尺度 | $\div \sqrt{d_k}$ |
| **Attention**（注意力） | 把分数变成权重，再按权重取用 value | $\operatorname{softmax}(\cdot)V$ |

一句话：

> **每个 query 先和所有 key 做点积打分，除以 $\sqrt{d_k}$ 把分数调到合适大小，softmax 变成权重，最后按权重把 value 混合起来。**

### 1.3 在注意力体系里的位置

```text
输入 X
  │
  ├── W_Q ──► Q ─┐
  ├── W_K ──► K ─┼──► 缩放点积注意力 ──► 每个头的输出
  └── W_V ──► V ─┘
                              │
                              ▼
                    拼接所有头 + W_O
                              │
                              ▼
                        多头注意力输出
```

所以：

- **缩放点积注意力**是“一个头”内部的计算；
- **多头注意力**是“多个头并行做缩放点积注意力，再拼接”；
- **Transformer Block** 再把多头注意力和前馈网络、残差、归一化组合起来。

> 记住这个层级，后面看代码时就不会把“一个头”和“整个多头层”混在一起。

## 2. 输入输出与形状

### 2.1 符号约定

| 符号 | 含义 | 说明 |
| --- | --- | --- |
| `...` | 任意前置维度 | 可以是 `(B,)`，也可以是 `(B,H)` |
| $T_q$ | query 的数量 | 自注意力里等于序列长度 $T$ |
| $T_k$ | key/value 的数量 | 自注意力里也等于 $T$；交叉注意力里可以不同 |
| $d_k$ | query/key 的维度 | 点积必须在这一维对齐 |
| $d_v$ | value 的维度 | 输出最后一维是 $d_v$，可以和 $d_k$ 不同 |

### 2.2 形状表

| 张量 | 形状 | 含义 |
| --- | --- | --- |
| $Q$ | `(..., T_q, d_k)` | 每个 query 的向量 |
| $K$ | `(..., T_k, d_k)` | 每个 key 的向量 |
| $V$ | `(..., T_k, d_v)` | 每个 key 对应的 value |
| $QK^\top$ | `(..., T_q, T_k)` | 打分矩阵：第 $i$ 行是 query $i$ 对所有 key 的分数 |
| softmax 后 | `(..., T_q, T_k)` | 权重矩阵：每一行加起来等于 1 |
| 输出 | `(..., T_q, d_v)` | 每个 query 得到一份混合后的 value |

### 2.3 三个形状上的关键点

1. **Q 和 K 的最后一维必须相同**，都是 $d_k$，否则点积无法进行。
2. **K 和 V 的倒数第二维必须相同**，都是 $T_k$，因为每个 key 对应一个 value。
3. **输出的最后一维是 $d_v$**，不是 $d_k$。如果 $d_v \ne d_k$，输出维度跟着 $V$ 走。

### 2.4 自注意力 vs 交叉注意力

| 类型 | Q 来自 | K/V 来自 | $T_q$ 与 $T_k$ |
| --- | --- | --- | --- |
| 自注意力（self-attention） | 同一序列 | 同一序列 | 通常相等 |
| 交叉注意力（cross-attention） | 解码器 | 编码器 | 可以不同 |

公式完全一样，区别只在输入来源。

### 2.5 带 batch 和 head 的形状

实际模型里最常见的是 4D：

```text
Q: (B, H, T, d_head)
K: (B, H, T, d_head)
V: (B, H, T, d_v)

scores: (B, H, T, T)
output: (B, H, T, d_v)
```

在标准多头自注意力里，通常取 `d_v = d_head`；但公式本身允许 `d_v` 与 `d_k` 不同。

其中：

```text
d_head = d_model / H
```

注意：缩放因子用的是 **`d_head`**，不是 `d_model`。这一点在 §5 和 §9 会反复强调。

## 3. 四个步骤：打分、缩放、softmax、加权求和

### 3.1 第一步：打分 $QK^\top$

```python
scores = Q @ K.transpose(-2, -1)
```

`K.transpose(-2, -1)` 把 `(..., T_k, d_k)` 变成 `(..., d_k, T_k)`，然后矩阵乘：

```text
(..., T_q, d_k) @ (..., d_k, T_k) -> (..., T_q, T_k)
```

`scores[i, j]` 是第 $i$ 个 query 和第 $j$ 个 key 的点积：

$$
\text{score}_{ij} = q_i \cdot k_j = \sum_{r=1}^{d_k} q_{i,r}k_{j,r}
$$

#### 点积为什么能当相似度

- 两个向量方向越接近，点积越大；
- 方向相反，点积为负；
- 正交，点积接近 0；
- 向量模长越大，点积也越大。

所以点积是“带方向的相似度”，但它会受维度大小影响——这正是下一步要缩放的原因。

### 3.2 第二步：缩放 $\div\sqrt{d_k}$

```python
scores = scores / math.sqrt(d_k)
```

这一步把分数的标准差拉回 1 左右，避免 softmax 变得过尖。详细推导见 §5。

### 3.3 第三步：softmax

```python
weights = scores.softmax(dim=-1)
```

沿着**最后一维**（key 维度）做 softmax：

$$
w_{ij}
=
\frac{\exp(\text{score}_{ij})}
{\sum_{j'=1}^{T_k}\exp(\text{score}_{ij'})}
$$

性质：

- 每个 $w_{ij} \ge 0$；
- 每一行 $\sum_j w_{ij}=1$；
- 分数越大，权重越大；
- 分数整体平移，权重不变；
- 分数整体放大，分布变尖。

### 3.4 第四步：加权求和 $\times V$

```python
output = weights @ V
```

```text
(..., T_q, T_k) @ (..., T_k, d_v) -> (..., T_q, d_v)
```

第 $i$ 个 query 的输出是：

$$
o_i = \sum_{j=1}^{T_k} w_{ij} v_j
$$

也就是说：

> **每个 query 的输出，是所有 value 的加权平均；权重由 query 和 key 的匹配程度决定。**

如果权重非负且和为 1，输出就是 value 的凸组合，落在所有 value 张成的凸包内。

### 3.5 把四步连起来

```python
import math

import torch


def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))
    weights = scores.softmax(dim=-1)
    weights = torch.nan_to_num(weights, nan=0.0)
    return weights @ V
```

这五行就是本文的核心。接下来逐块解释。

## 4. 手算一个 3 个 token 的例子

### 4.1 输入

```python
import math
import torch
import torch.nn.functional as F

Q = torch.tensor([
    [1.0, 0.0],   # token 0 的 query
    [0.0, 1.0],   # token 1 的 query
    [1.0, 1.0],   # token 2 的 query
])

K = torch.tensor([
    [1.0, 0.0],   # token 0 的 key
    [0.0, 1.0],   # token 1 的 key
    [1.0, 1.0],   # token 2 的 key
])

V = torch.tensor([
    [1.0, 0.0],   # token 0 的 value
    [0.0, 1.0],   # token 1 的 value
    [2.0, 0.0],   # token 2 的 value（故意放大，方便观察）
])

d_k = Q.shape[-1]   # 2
```

### 4.2 打分

```python
scores = Q @ K.T / math.sqrt(d_k)
print(scores)
```

输出：

```text
tensor([[0.7071, 0.0000, 0.7071],
        [0.0000, 0.7071, 0.7071],
        [0.7071, 0.7071, 1.4142]])
```

怎么读：

- 第 0 行：query 0 和 key 0、key 2 完全同向，分数 0.7071；和 key 1 正交，分数 0；
- 第 1 行：query 1 和 key 1、key 2 相关；
- 第 2 行：query 2 和三个 key 都相关，和 key 2 最相关（1.4142）。

### 4.3 softmax

```python
weights = scores.softmax(dim=-1)
print(weights)
```

输出：

```text
tensor([[0.4011, 0.1978, 0.4011],
        [0.1978, 0.4011, 0.4011],
        [0.2483, 0.2483, 0.5035]])
```

每一行加起来都是 1。比如第 0 行：

```text
0.4011 + 0.1978 + 0.4011 = 1.0000
```

### 4.4 加权求和

```python
output = weights @ V
print(output)
```

输出：

```text
tensor([[1.2033, 0.1978],
        [1.0000, 0.4011],
        [1.2552, 0.2483]])
```

以第 0 行为例：

```text
0.4011 * [1, 0]
+ 0.1978 * [0, 1]
+ 0.4011 * [2, 0]
= [1.2033, 0.1978]
```

这正是“按权重把 value 混合起来”。

### 4.5 和 PyTorch 内置实现对照

```python
ref = F.scaled_dot_product_attention(Q, K, V)
print("match:", torch.allclose(output, ref, atol=1e-6))
```

输出：

```text
match: True
```

> 手算和内置实现一致，说明四步理解正确。

### 4.6 这个例子里的几个检查点

- `scores` 形状 `(3,3)`：3 个 query × 3 个 key；
- `weights` 每一行和为 1；
- `output` 形状 `(3,2)`：最后一维跟着 `V` 走；
- 第 0 个 token 的输出 x 分量被 value 2 拉大，因为它的权重有 40% 给了 value 2。

## 5. 为什么除以 $\sqrt{d_k}$

### 5.1 点积的方差会随维度增长

假设 $q$ 和 $k$ 的每个分量都是独立同分布，均值 0、方差 1：

$$
q_i \sim \mathcal{N}(0,1),\qquad k_i \sim \mathcal{N}(0,1)
$$

点积是：

$$
q\cdot k = \sum_{i=1}^{d_k} q_i k_i
$$

每一项 $q_i k_i$ 的均值是 0，方差是：

$$
\operatorname{Var}(q_i k_i)
=
\mathbb{E}[q_i^2]\mathbb{E}[k_i^2]
=
1 \cdot 1
=
1
$$

由独立性，方差可加：

$$
\operatorname{Var}(q\cdot k)
=
\sum_{i=1}^{d_k}\operatorname{Var}(q_i k_i)
=
d_k
$$

所以：

$$
\operatorname{std}(q\cdot k)=\sqrt{d_k}
$$

**维度越大，点积的数值尺度越大。** 例如：

| $d_k$ | 点积标准差 |
| ---: | ---: |
| 16 | 4 |
| 64 | 8 |
| 256 | 16 |
| 1024 | 32 |

### 5.2 不缩放会怎样

分数一大，softmax 就变成“尖峰”：

```python
import math
import torch

torch.manual_seed(0)

for d in [16, 64, 256]:
    q = torch.randn(1, 1, d)
    k = torch.randn(1, 64, d)
    raw = q @ k.transpose(-2, -1)

    for name, scores in [("raw", raw), ("scaled", raw / math.sqrt(d))]:
        p = scores.softmax(dim=-1)
        entropy = -(p * p.clamp_min(1e-30).log()).sum(-1).mean().item()
        print(
            f"d_k={d:3d} {name:6s} "
            f"max_prob={p.max().item():.6f} entropy={entropy:.4f}"
        )
```

实际输出：

```text
d_k= 16 raw    max_prob=0.513118 entropy=1.6034
d_k= 16 scaled max_prob=0.085820 entropy=3.7441
d_k= 64 raw    max_prob=0.542515 entropy=0.8162
d_k= 64 scaled max_prob=0.161177 entropy=3.2629
d_k=256 raw    max_prob=0.993724 entropy=0.0411
d_k=256 scaled max_prob=0.079237 entropy=3.7332
```

怎么读：

- `max_prob` 是这一行最大的注意力权重；
- `entropy` 是权重分布的熵，越大越“平均”，越小越“尖”；
- **不缩放**时，$d_k=256$ 的最大权重已经到 0.99，熵接近 0，模型几乎只盯一个位置；
- **缩放**后，最大权重稳定在 0.08~0.16，熵稳定在 3.7 附近，和 $d_k$ 关系不大。

### 5.3 为什么尖峰会影响训练

softmax 的雅可比矩阵里有一项：

$$
\frac{\partial p_i}{\partial z_i}=p_i(1-p_i)
$$

当某个 $p_i\to 1$ 时：

$$
p_i(1-p_i)\to 0
$$

也就是说，**softmax 饱和时，回传到分数的梯度会变得非常小**。分数再大，梯度也传不回去，训练就容易停滞。

缩放的作用是：

> 把点积的方差从 $d_k$ 拉回 1，让 softmax 始终处在“既不平均、也不饱和”的健康温度。

### 5.4 为什么是 $\sqrt{d_k}$ 而不是 $d_k$

我们要做的是“除以标准差”：

$$
\frac{q\cdot k}{\operatorname{std}(q\cdot k)}
=
\frac{q\cdot k}{\sqrt{d_k}}
$$

如果除以 $d_k$，会把分数压得过头，softmax 变得过平；如果除以 1，又压不住高维点积。

> 记住：**方差是 $d_k$，标准差才是 $\sqrt{d_k}$。**

### 5.5 “温度”视角

softmax 可以看成：

$$
\operatorname{softmax}\left(\frac{z}{T}\right)
$$

其中 $T$ 是温度：

- $T$ 小 → 分布尖；
- $T$ 大 → 分布平。

在缩放点积注意力里：

$$
T=\sqrt{d_k}
$$

所以缩放因子就是在给 softmax 设定一个**随维度自动调整的温度**。

### 5.6 $d_k$ 是每个头的维度

在多头注意力里：

$$
d_k = d_{head} = \frac{d_{model}}{H}
$$

不是 $d_{model}$。

例如：

```text
d_model = 512
H = 8
d_head = 64
```

缩放因子是：

```text
1 / sqrt(64) = 1/8
```

不是：

```text
1 / sqrt(512)
```

> 这是 CS336 里非常常见的错误：把所有头拼在一起的维度当成了 $d_k$。

## 6. Mask：哪些位置不能看

### 6.1 为什么需要 mask

语言模型训练时，位置 $i$ 只能看到 $j \le i$ 的位置，不能看未来。否则模型可以直接“抄答案”，推理时没有未来可看，就废了。

因果 mask 是一个下三角矩阵：

```text
        位置0   位置1   位置2   位置3
位置0 [   ✓       ✗       ✗       ✗  ]
位置1 [   ✓       ✓       ✗       ✗  ]
位置2 [   ✓       ✓       ✓       ✗  ]
位置3 [   ✓       ✓       ✓       ✓  ]
```

### 6.2 mask 加在 softmax 之前

正确做法：

```python
scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
scores = scores.masked_fill(~causal_mask, float("-inf"))
weights = scores.softmax(dim=-1)
```

为什么必须在 softmax 之前？

- softmax 的分母是所有 key 的指数和；
- 如果先把被屏蔽位置的权重算出来再乘 0，它们仍然参与了分母，会改变其他位置的相对权重；
- 用 $-\infty$ 在 softmax 之前屏蔽，指数为 0，分母里自然不包含它们。

### 6.3 True/False 的约定

CS336 讲义和 `F.scaled_dot_product_attention` 的布尔 mask 约定：

> **`True` = 允许注意，`False` = 屏蔽。**

所以自己实现时：

```python
scores = scores.masked_fill(~mask, float("-inf"))
```

这里 `~mask` 把“允许”变成“屏蔽”。

但要注意：

| API | `True` 的含义 |
| --- | --- |
| CS336 讲义 / `F.scaled_dot_product_attention` | **允许**注意 |
| `nn.MultiheadAttention` 的 `attn_mask` | **屏蔽** |

换 API 前一定确认约定，否则形状对、数值全错，而且不报错。

### 6.4 因果 mask 的实现

```python
T = 5
causal_mask = torch.tril(torch.ones(T, T, dtype=torch.bool))
print(causal_mask)
```

输出：

```text
tensor([[ True, False, False, False, False],
        [ True,  True, False, False, False],
        [ True,  True,  True, False, False],
        [ True,  True,  True,  True, False],
        [ True,  True,  True,  True,  True]])
```

然后：

```python
scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
scores = scores.masked_fill(~causal_mask, float("-inf"))
weights = scores.softmax(dim=-1)
```

### 6.5 前缀不变性：一个很好用的自检

因果注意力的定义性质是：

> 改动后面的 token，前面位置的输出必须不变。

```python
import math
import torch
import torch.nn.functional as F

torch.manual_seed(0)
T = 4
d = 8

q = torch.randn(1, T, d)
k = torch.randn(1, T, d)
v = torch.randn(1, T, d)
causal = torch.tril(torch.ones(T, T, dtype=torch.bool))

out_a = F.scaled_dot_product_attention(q, k, v, attn_mask=causal)

# 只改最后一个 token 的 value
v2 = v.clone()
v2[:, 3] += 100.0
out_b = F.scaled_dot_product_attention(q, k, v2, attn_mask=causal)

print("prefix unchanged:", torch.allclose(out_a[:, 0], out_b[:, 0], atol=1e-6))
```

输出：

```text
prefix unchanged: True
```

这个检查非常有用：如果你改动未来 token 后，前面位置的输出变了，说明 mask 没生效或语义反了。

### 6.6 整行被屏蔽会怎样

如果某个 query 的所有 key 都被屏蔽：

```text
scores 某一行 = [-inf, -inf, -inf]
```

softmax 的分母是 0，数学上会得到 `nan`。

不同实现的处理：

- 纯 `softmax`：得到 `nan`；
- `F.scaled_dot_product_attention`：对被完全屏蔽的行返回 0（实测）；
- CS336 适配器：手动 `nan_to_num(attn, nan=0.0)`，与 PyTorch 对齐。

```python
torch.manual_seed(0)

q = torch.randn(1, 2, 3)
k = torch.randn(1, 3, 3)
v = torch.randn(1, 3, 3)

# 第 0 行可以看第 0 个 key；第 1 行全屏蔽
mask = torch.tensor([[[True, False, False],
                      [False, False, False]]])

scores = q @ k.transpose(-2, -1) / math.sqrt(q.shape[-1])
scores = scores.masked_fill(~mask, float("-inf"))
weights = scores.softmax(dim=-1)
weights = torch.nan_to_num(weights, nan=0.0)

manual = weights @ v
ref = F.scaled_dot_product_attention(q, k, v, attn_mask=mask)
print(manual)
print(ref)
```

输出（第 1 行全 0）：

```text
tensor([[[ 0.1227, -0.5663,  0.3731],
         [ 0.0000,  0.0000,  0.0000]]])
tensor([[[ 0.1227, -0.5663,  0.3731],
         [ 0.0000,  0.0000,  0.0000]]])
```

> 在 padding 很多的 batch 里，整行屏蔽是可能发生的。不要在残差里留下 `nan`。

### 6.7 mask 的形状与广播

mask 的形状必须能广播到 `scores`：

```text
scores: (..., T_q, T_k)
mask:   (..., T_q, T_k)
```

常见情况：

| 场景 | mask 形状 |
| --- | --- |
| 单头，有 batch | `(B, T_q, T_k)` |
| 多头 | `(B, H, T_q, T_k)` |
| 所有头共用 | `(B, 1, T_q, T_k)` 或 `(T_q, T_k)` |

只要最后一维是 `T_k`，并且前面的维度能广播，就可以。

## 7. PyTorch 实现与对拍

### 7.1 手写实现

```python
import math

import torch
import torch.nn.functional as F


def scaled_dot_product_attention(Q, K, V, mask=None):
    """支持任意前置维度，例如 (B,T,d) 或 (B,H,T,d)。"""
    d_k = Q.shape[-1]

    # ① 打分: (..., Tq, d_k) @ (..., d_k, Tk) -> (..., Tq, Tk)
    scores = Q @ K.transpose(-2, -1)

    # ② 缩放
    scores = scores / math.sqrt(d_k)

    # ③ 掩码：True = 允许，False = 屏蔽
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))

    # ④ softmax + 加权求和
    weights = scores.softmax(dim=-1)

    # 整行被屏蔽时，softmax 会产生 nan；对齐 PyTorch 的 0 行为
    weights = torch.nan_to_num(weights, nan=0.0)

    return weights @ V
```

### 7.2 3D 和 4D 都能跑

```python
torch.manual_seed(0)

# 3D: (B, Tq, d_k)
q = torch.randn(2, 5, 4)
k = torch.randn(2, 6, 4)
v = torch.randn(2, 6, 6)
mask = torch.rand(2, 5, 6) > 0.3

out = scaled_dot_product_attention(q, k, v, mask)
ref = F.scaled_dot_product_attention(q, k, v, attn_mask=mask)

print("3D:", tuple(out.shape), torch.allclose(out, ref, atol=1e-6))
```

```text
3D: (2, 5, 6) True
```

4D 版本：

```python
q = torch.randn(2, 3, 5, 4)
k = torch.randn(2, 3, 6, 4)
v = torch.randn(2, 3, 6, 6)
mask = torch.rand(2, 3, 5, 6) > 0.3

out = scaled_dot_product_attention(q, k, v, mask)
ref = F.scaled_dot_product_attention(q, k, v, attn_mask=mask)

print("4D:", tuple(out.shape), torch.allclose(out, ref, atol=1e-6))
```

```text
4D: (2, 3, 5, 6) True
```

> 注意：`d_k=4`，`d_v=6`，输出最后一维是 6。不要把 `d_v` 写成 `d_k`。

### 7.3 直接用 PyTorch 内置函数

```python
out = F.scaled_dot_product_attention(Q, K, V, attn_mask=mask)
```

它默认的缩放也是：

$$
\frac{1}{\sqrt{d_k}}
$$

其中 `d_k = Q.size(-1)`。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `attn_mask` | 布尔或加性 mask |
| `dropout_p` | dropout 概率，训练时用 |
| `is_causal` | 是否使用因果 mask（要求方阵） |
| `scale` | 自定义缩放因子，默认 `1/sqrt(d_k)` |

如果使用 `is_causal=True`：

```python
out = F.scaled_dot_product_attention(Q, K, V, is_causal=True)
```

它等价于传入一个下三角 mask，适合标准因果自注意力。

### 7.4 手写 vs 内置

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| 手写 `softmax(QK^T/√d_k)V` | 透明、好调试、适合学习 | 慢；显式存 `T×T` 矩阵 |
| `F.scaled_dot_product_attention` | 快；可能用 FlashAttention 等 kernel | 内部实现是黑盒，初学时不直观 |

建议：

- 先手写一遍，确认形状和数值；
- 再用内置实现做对拍；
- 真正训练时用内置实现。

### 7.5 数值稳定

`torch.softmax` 内部会做“减最大值”的稳定处理，所以直接写：

```python
weights = scores.softmax(dim=-1)
```

通常没问题。

但要注意：

- 如果整行都是 `-inf`，softmax 仍会产生 `nan`；
- 用 `torch.nan_to_num(..., nan=0.0)` 对齐 PyTorch 的行为；
- 不要用 `-1e9` 代替 `-inf`：分数很大时 `-1e9` 压不住，可能得到非零权重。

## 8. 从单头到多头

### 8.1 多头就是多次 SDPA

多头注意力的流程：

```text
X: (B, T, d_model)
  │
  ├── W_Q ──► Q: (B, T, d_model)
  ├── W_K ──► K: (B, T, d_model)
  └── W_V ──► V: (B, T, d_model)
  │
  ▼ 拆头
Q,K,V: (B, H, T, d_head)
  │
  ▼ 每个头独立做 SDPA
heads: (B, H, T, d_head)
  │
  ▼ 合头
(B, T, d_model)
  │
  ▼ W_O
output: (B, T, d_model)
```

### 8.2 形状表

| 步骤 | 形状 |
| --- | --- |
| 输入 `X` | `(B, T, d_model)` |
| `Q/K/V` 投影 | `(B, T, d_model)` |
| 拆头 | `(B, H, T, d_head)` |
| 每头分数 | `(B, H, T, T)` |
| 每头输出 | `(B, H, T, d_head)` |
| 合头 | `(B, T, d_model)` |
| `W_O` 后 | `(B, T, d_model)` |

### 8.3 关键：缩放用 `d_head`

```python
d_head = d_model // num_heads
scores = qh @ kh.transpose(-2, -1) / math.sqrt(d_head)
```

不是：

```python
scores = qh @ kh.transpose(-2, -1) / math.sqrt(d_model)   # 错
```

因为每个头只在自己的 `d_head` 维子空间里做点积。

## 10. 常见问题 FAQ

### Q1：为什么是 $QK^\top$，不是 $KQ^\top$？

因为我们要得到“query × key”的矩阵：

```text
Q: (T_q, d_k)
K: (T_k, d_k)
QK^T: (T_q, T_k)
```

第 $i$ 行是第 $i$ 个 query 对所有 key 的分数。

### Q2：$d_k$ 和 $d_v$ 必须相等吗？

不必须。

- $Q$ 和 $K$ 的最后一维必须相等（要能做点积），都是 $d_k$；
- $V$ 的最后一维是 $d_v$，可以不同；
- 输出最后一维是 $d_v$。

在标准多头自注意力里，通常 $d_k=d_v=d_{head}$。

### Q3：为什么 softmax 沿最后一维？

`scores` 的形状是 `(..., T_q, T_k)`，最后一维是 key。每个 query 要对所有 key 归一化，所以沿最后一维做 softmax。

### Q4：mask 可以加在 softmax 之后吗？

不可以。softmax 的分母包含所有 key 的指数；如果先算权重再乘 0，被屏蔽的位置仍然影响了分母，其他位置的权重就错了。

### Q5：`F.scaled_dot_product_attention` 的 mask 是 True=允许还是 True=屏蔽？

CS336 讲义和 `F.scaled_dot_product_attention` 的布尔 `attn_mask`：**True = 允许注意**。

但 `nn.MultiheadAttention` 的 `attn_mask` 是**True = 屏蔽**。换 API 要确认。

### Q6：为什么整行 mask 会得到 NaN？

softmax 的分母是：

$$
\sum_j \exp(\text{score}_{ij})
$$

如果整行都是 $-\infty$，每一项都是 0，分母是 0，$0/0$ 就是 NaN。

处理方式：

- 避免整行屏蔽；
- 或者 `nan_to_num` 成 0；
- PyTorch 的 SDPA 对被完全屏蔽的行返回 0。

### Q7：缩放因子可以学习吗？

可以，有人尝试过可学习的温度，但主流实现仍用固定的 $1/\sqrt{d_k}$。固定缩放提供了稳定的先验，训练更简单。

### Q8：为什么不用余弦相似度？

余弦相似度会丢掉模长信息，而且需要额外的归一化；缩放点积可以直接用矩阵乘批量计算，和 GPU 更契合。

### Q9：dropout 加在哪里？

通常加在 softmax 之后的权重上：

```python
weights = scores.softmax(dim=-1)
weights = F.dropout(weights, p=dropout_p, training=self.training)
output = weights @ V
```

`F.scaled_dot_product_attention` 也提供 `dropout_p` 参数。

### Q10：训练时和推理时的 SDPA 有什么不同？

训练时整段序列一次算完，可以并行；推理时逐 token 生成，通常要缓存 K/V（KV cache），避免重复计算历史 token 的 key/value。

### Q11：为什么注意力的计算量是 $O(T^2 d)$？

`scores = QK^T` 要做 $T_q \times T_k$ 次点积，每次 $d_k$ 维：

$$
O(T_q T_k d_k)
$$

当 $T_q=T_k=T$ 时就是 $O(T^2 d)$。序列长度翻倍，计算量约四倍。

### Q12：手写实现和内置实现结果差一点，正常吗？

浮点运算顺序不同，可能有 `1e-6` 到 `1e-5` 的误差，正常。测试容差是 `atol=1e-5`；如果差到 `1e-3`，通常是真的漏了缩放或 mask 错了。

## 11. 小结与练习

### 11.1 一句话总结

> **缩放点积注意力 = 每个 query 用点积给所有 key 打分，除以 $\sqrt{d_k}$ 控制温度，softmax 变成权重，再按权重把 value 混合起来。**

### 11.2 五个关键点

1. **打分**：$QK^\top$，形状 `(..., T_q, T_k)`；
2. **缩放**：除以 $\sqrt{d_k}$，$d_k$ 是每个头的维度；
3. **softmax**：沿 key 维归一化，每行和为 1；
4. **加权求和**：权重 `@ V`，输出 `(..., T_q, d_v)`；
5. **mask**：在 softmax 之前加 $-\infty$，`True` 表示允许。

### 11.3 练习

1. **手算**：把 §4 的 `V` 改成 `[[1,0],[0,1],[-1,0]]`，重新算输出，验证第 0 行 x 分量变成 0。
2. **去掉缩放**：用 $d_k=256$ 比较 raw 和 scaled 的 `max_prob` 与 entropy，观察 softmax 饱和。
3. **mask 语义**：构造一个 4×4 因果 mask，分别用 `masked_fill(~mask, -inf)` 和 `masked_fill(mask, -inf)`，看哪个是下三角。
4. **前缀不变性**：改动最后一个 token 的 V，验证前面位置的输出不变。
5. **4D 对拍**：把 3D 的 `(B,T,d)` 拆成 `(B,H,T,d_head)`，用 `F.scaled_dot_product_attention` 对拍。
6. **整行屏蔽**：构造一行全 False 的 mask，观察手写实现和 PyTorch 的输出，确认都为 0。
7. **成本估算**：给定 $T=2048$、$d_k=64$、$H=8$，估算 `scores` 在 fp16 下占多少显存。
