## 0. 阅读前的准备：符号、形状与术语

### 0.1 符号约定

| 符号 | 含义 | 一句话解释 |
| --- | --- | --- |
| $B$ | batch size | 一次同时训练多少条序列 |
| $T$ | sequence length（context length） | 一条序列有多少个 token，也是模型一次能看多长 |
| $D$ | d_model | 每个 token 在模型内部用多少个数来描述（隐藏维度） |
| $V$ | vocab size | 词表里一共有多少个 token |
| $H$ | n_heads | 注意力头数；每个头分到 $d_{head} = D / H$ 维 |
| $d_{ff}$ | feed-forward 中间层维度 | FFN 内部" expands 再压回"的中间宽度 |

### 0.2 形状记号：`(B, T, D)`

模型内部流动的"水"始终是三维张量：

- `B`：**同时**处理多少条序列（互不干扰，像流水线上的多条传送带）
- `T`：每条序列有多长（位置轴，模型一次能看多远）
- `D`：每个位置上的信息有多少个数字（特征轴）

只有输入输出两端是"例外"：

- 模型**输入**：整数 ID，张量形状 `(B, T)`
- 模型**输出**：概率分布，张量形状 `(B, T, V)`——每个位置都给出一份"下一个词是谁"的概率

> **给新手的提醒**：`(B, T, D)` 中的 `D` 那一维在绝大多数操作里是"被整体对待"的（一次矩阵乘法、一个 LayerNorm 都作用在 D 维上），而 `T` 维会被注意力反复扫描。凡是看到"逐位置"（position-wise）这个词，意思就是"每个位置各自算，互不干涉"。

### 0.3 术语速查表

| 术语 | 白话解释 |
| --- | --- |
| token（词元） | 分词后的最小单位，可能是字、词的一部分或一个字节 |
| embedding（嵌入） | 给每个 token 配的一个 D 维向量，模型的"内部身份证" |
| logit（对数几率） | 线性层输出的未归一化分数，可以是正负数 |
| softmax | 把一堆分数变成"加起来等于 1"的概率 |
| attention（注意力） | 让每个位置按相关度去"取用"其他位置信息的机制 |
| Q / K / V | 注意力里的"查询 / 键 / 值"，类比数据库检索 |
| mask（掩码） | 屏蔽掉不该看的位置（语言模型里是"未来"） |
| 残差连接 | 把子层输出**加回**它的输入，y = x + f(x) |
| 归一化（Norm） | 把一组数调整到合适的尺度，训练才稳 |
| pre-norm | 先归一化再进子层，子层输出加回主干 |
| 困惑度（perplexity） | 衡量模型"有多意外"的指标，数值越低越好 |

### 0.4 一句话总览

> **Transformer 的工作**：把"我到目前为止写的这些字"变成一个向量，再把这个向量翻译成"下一个字最可能是什么"的一串概率。

整个模型就是把这个动作重复很多遍，每次都让它更准一点。

## 1. Transformer 整体介绍：背景、用途与基本直觉

### 1.1 背景：从 RNN 到 Transformer

2017 年之前，主流做法是 RNN/LSTM：像人**从头到尾逐字读**句子，读一个词就把之前的信息压缩进一个"记忆向量"，再读下一个。

这种做法有两个硬伤：

1. **不能并行**：第 5 个词必须等第 4 个词处理完，GPU 的并行算力用不上；
2. **长距离遗忘**：句子很长时，最早的内容在"记忆向量"里被稀释了。

《Attention Is All You Need》（Vaswani 等，2017）提出的做法反其道而行：**每个词同时去查看句子里所有其他词，自己决定该重点看谁**。这一下子把顺序依赖拿掉了，于是整个句子可以一次性并行算完，长距离依赖也不再需要靠"记忆"硬扛。

CS336 Assignment 1 要你从零实现的，就是这种 **decoder-only Transformer**（也就是 GPT 那一类）：只做"看上文 → 猜下一个词"。

### 1.2 它用在哪

- **语言模型**：GPT、Llama、Claude 这一族（本作业的目标）
- **机器翻译 / 摘要**：早期 Transformer 的原始应用
- **编码器**：BERT 那一类（双向理解，不做生成）
- **今天的多模态大模型**：图像、音频最终也被转成 token 走同一条流水线

### 1.3 基本直觉：写下一个词，本质是算条件概率

我们写故事时，每写一个字，脑子里其实都在算："在'从前有只小狐狸，它'这句话后面，我下一个字最可能写什么？"

数学上就是：

$$
P(x_{i+1} \mid x_1, x_2, \dots, x_i)
$$

Transformer 就是一个**把这个条件概率算出来**的机器。它的流水线是：

1. 把每个字变成一个能计算的向量（**映射**）；
2. 让每个位置去参考其他位置，把相关信息**揉进自己的向量**（**注意力**）；
3. 反复揉若干层（**堆叠**）；
4. 最后把向量翻译回"词表上的打分"（**输出**）。

### 1.4 数据流总览

```text
  原始文本
     │
     ▼  ① 分词（BPE）："The cat sat" → [464, 2068, 333]
  token ID 序列   形状 (B, T)
     │
     ▼  ② 查表嵌入：每个 ID 换成一个 D 维向量
  向量序列       形状 (B, T, D)
     │
     ▼  ③ 注入位置信息（RoPE 加在 Q/K 上）
     │
     ▼  ④ N 层 Transformer Block（每层 = 注意力 + 前馈 + 残差 + 归一化）
  向量序列       形状 (B, T, D)
     │
     ▼  ⑤ 最终归一化 + 输出投影（LM head）：D 维 → V 维
  logits         形状 (B, T, V)
     │
     ▼  ⑥ softmax：分数 → 概率
  概率分布       形状 (B, T, V)
```

> **记忆这张图**：往后写代码时，你写的每个模块都应该能在这张图上指出位置。写完回头对一遍，是检查有没有漏环节最快的办法。

### 1.5 五个部件的分工

| 部件 | 回答的问题 | 类比 |
| --- | --- | --- |
| 分词器 | 这段文字被切成哪些"块"？ | 切麻将牌 |
| 嵌入层 | 每个"块"在模型眼里长什么样？ | 给每个人发一张写着"身份+性格"的卡片 |
| 注意力 | 我该重点听谁说话？ | 圆桌讨论，各自决定重点关注谁 |
| 前馈网络 | 听到之后我该怎么消化？ | 听完自己做笔记、形成看法 |
| 输出层 | 综合我听到的，下一句该说什么？ | 举手发言，报告结论 |

**注意力负责"信息交换"，前馈网络负责"就地思考"**——记住这句话，后面的细节都好理解。

## 2. 输入阶段：文本 → token ID 序列

### 2.1 第一步：分词（承接 BPE 那一节）

模型不认识字符串，只认识整数。所以第一步是把文本切成 token、再换成整数 ID。

这一步就是你前面实现的 BPE 分词器在做的事：

```text
"Hello world!"  →  预分词  →  ["Hello", " world", "!"]  →  BPE 合并  →  ID 序列
```

几个要点回顾（详见同目录的 `BPE算法原理.md`）：

- **字节级（byte-level）**：任何字符都能拆成字节，所以永远不会出现"词表里没有这个字"的 OOV 崩溃；
- **合并规则有优先级**：规则表顺序不同，同一个词的切法就不同；
- **特殊 token**（如 `<|endoftext|>`）是原子，不参与合并。

### 2.2 第二步：拼成定长训练样本

训练时每个样本必须是**固定长度** $T$（context length），否则矩阵运算无法批量进行。于是把整份语料当成一条长河，按 $T$ 长一段一段切下来：

```text
语料流： [tok][tok][tok][tok][tok][tok][tok][tok][tok][tok]...
切块后： |---- 块1 (T=4) ----||---- 块2 (T=4) ----|
```

这样切有个好处：块与块之间不需要 padding（补空白），每个 token 都实打实地参与了训练，效率很高。

`<|endoftext|>` 这类特殊 token 在这里派上用场——它标记"一篇文档到此结束"，切块时就不会把两篇文档的尾巴和开头硬拼在一起。

### 2.3 第三步：错位一个位置，得到"标签"

这是语言模型训练最关键的一个小技巧。对一个长度为 $T$ 的 token 序列：

```text
输入（input）:  [t0] [t1] [t2] [t3]
标签（label）:      [t1] [t2] [t3] [t4]
```

也就是"用前 $i$ 个词去预测第 $i+1$ 个词"。这样**一个长度为 T 的样本，一次前向传播就同时产生了 T 个训练信号**，而不是每次只学一个词。

- 输入张量形状：`(B, T)`
- 标签张量形状：`(B, T)`

两者内容一样，只是错开了一位。

### 2.4 输入阶段的产出

到这一步结束，你手里是一个整数张量 `(B, T)`。它不含任何语义信息——只是"第几个词是第几号"。

**接下来的映射阶段，才是把这些编号变成模型能运算的向量。**

## 3. 映射阶段：token ID → 向量

### 3.1 Embedding：一张大查找表

嵌入层本身没有数学含量，就是一张表：

- 行数 = 词表大小 $V$
- 列数 = 隐藏维度 $D$
- 查表方式：`embedding[token_id]` 取出对应那一行

```text
             D 维向量
token 0  → [ 0.31, -1.02,  0.88, ... ]   ← 第 0 行
token 1  → [-0.44,  0.15,  1.30, ... ]   ← 第 1 行
token 2  → [ 0.77,  0.02, -0.61, ... ]   ← 第 2 行
  ...
```

每个 token 都有一张"身份证"。这张表里的数字**不是人写的，是训练学出来的**：经常一起出现的词，向量会慢慢靠拢。

### 3.2 为什么不能直接用 ID 或 one-hot

如果直接把 ID 当数字用，会出三个问题：

1. **ID 没有语义**：`"cat"` 的 ID 是 2068，`"dog"` 是 3290，但 2068 和 3290 挨得近纯属编号顺序的巧合，跟语义无关。模型会误以为 ID 大的词"更大/更重要"。
2. **one-hot 太稀疏**：one-hot 向量是"第 2068 位是 1，其余全是 0"，维度等于词表大小。词表 1 万就是 1 万维，其中 9999 个是 0，信息密度极低，而且维度随词表膨胀。
3. **无法表达"相似"**：embedding 把词放进连续空间，语义相近的词自然距离近。这才是"特征"该有的样子。

### 3.3 形状变化：`(B, T)` → `(B, T, D)`

查表对每个位置独立进行，所以：

- 输入：`(B, T)` 整数
- 输出：`(B, T, D)` 浮点

**至此模型第一次"看见"了实数世界。** 后面所有的矩阵乘法、归一化、注意力，作用的都是这个 `(B, T, D)` 的张量。

### 3.4 一个值得记住的细节

> 很多现代语言模型让**输入嵌入**和**输出投影（LM head）共享同一张表**（业内叫"权重绑定"），这样词表矩阵只需存一份、也隐式地鼓励"输入时怎么表示，输出时也怎么表示"。作业讲义把这两者写成了两个独立模块（Embedding 与 Linear），是否共享属于实现选择，不影响你理解整体流程。

## 4. 核心变换：Transformer Block 内部

这一节是整个模型的心脏。作业里 `num_layers` 层的 Block 结构**完全相同**，只是参数不同——就像同一款发动机，装了几台而已。

### 4.1 Block 全貌：pre-norm 结构

本作业采用 **pre-norm** 的 Block（讲义 3.4 节、图 2）：

```text
                 ┌──────────────────────────┐
                 │                          │
    x ──────────►│  RMSNorm  →  注意力      │──► (+) ──► y
                 │  (RoPE 加在 Q/K 上)      │      ▲
                 └──────────────────────────┘      │
                                                 │
                 x (=y) ───────────────────────────┘  残差相加

                 ┌──────────────────────────┐
                 │                          │
    y ──────────►│  RMSNorm  →  SwiGLU FFN  │──► (+) ──► z
                 │                          │      ▲
                 └──────────────────────────┘      │
                                                 │
                 y (=z) ───────────────────────────┘  残差相加
```

写成公式就是两行：

$$
y = x + \text{MultiHeadSelfAttention}(\text{RMSNorm}(x))
$$

$$
z = y + \text{SwiGLU}(\text{RMSNorm}(y))
$$

注意三点：

- **子层前先归一化**（pre-norm），这就是 "pre" 的含义；
- **子层输出是加回去的**（残差），不是替换掉的；
- **注意力在前、FFN 在后**，每层各来一遍。

### 4.2 RMSNorm：让尺度稳住

RMSNorm（Zhang 等，2019）做的事：把一个 D 维向量里的每个数，按"这个向量的整体大小"统一缩放，再乘一个**可学习的增益** $g$：

$$
\text{RMSNorm}(a_i) = \frac{a_i}{\sqrt{\frac{1}{d_{model}}\sum_j a_j^2 + \varepsilon}} \cdot g_i
$$

- 和 LayerNorm 的区别：LayerNorm 减均值（把数据中心挪到 0），RMSNorm 只除以均方根（**不减均值**），更简单也更省；
- $g$ 是可学习参数：模型可以自己决定"哪些维度要放大、哪些要压小"；
- $\varepsilon$ 是防止除零的小常数。

**为什么需要它？** 深层网络里数值会越传越极端（过大或过小），一旦梯度被压扁，学习就停滞了。归一化相当于每层都把数值拉回"健康区间"。

> 顺带一提：pre-norm 结构对参数初始化的鲁棒性明显好于 post-norm，这在讲义 3.3.1 节有讨论。

### 4.3 注意力：Q/K/V 的"图书馆检索"类比

注意力是本作业最核心、也最容易懵的部分。用一个类比拆开：

> **图书馆检索**
>
> - 你（Query）拿着一张检索单走进图书馆，上面写着"我想找关于'狗'的书"；
> - 书架上每本书都有标签（Key），标签写着"这本书讲的是狗"、"这本书讲的是猫"……
> - 检索单和标签的**匹配程度**决定了这本书被"取走"的价值（Value）——标签越贴题，书里的内容对你越有用；
> - 最后你取回的是"按贴题程度加权平均后的内容"。

翻译成公式：

$$
\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V
$$

分三步看：

**第一步：算匹配分（打分）**
$QK^\top$ 给出"每个查询与每个键的相似度"。这一步输出的形状是 `(B, H, T, T)`——$T \times T$ 的分数表，**每行是"我在向谁提问"，每列是"谁在被提问"**。

**第二步：softmax 变成权重**
每一行做 softmax，变成加起来等于 1 的权重分布："我对 A 关注 60%，对 B 关注 25%，对 C 关注 15%"。

**第三步：按权重取内容**
用这组权重去加权求和所有 $V$：

```text
输出 = 0.60 × V_A + 0.25 × V_B + 0.15 × V_C
```

**Q、K、V 从哪来？** 都是从当前层的向量 $x$ 经过三个可学习矩阵线性变换得到的：

$$
Q = x W_Q, \quad K = x W_K, \quad V = x W_V
$$

同一个词，在"提问"和"作答"两个角色下会学出不同的表示——这正是为什么要分成 Q 和 V。

### 4.4 因果掩码：不能偷看未来

语言模型在预测第 $i+1$ 个词时，只能看到 $x_1 \dots x_i$，绝不能看到 $x_{i+1}$（那等于直接看答案）。实现上就是在 softmax **之前**把"未来"那一半的分数设成一个极小的数（通常记作 $-\infty$），softmax 之后它们的权重就变成 0。

一个 4 个 token 的序列，注意力权重矩阵长这样（对角线及以下可见）：

```text
        位置0   位置1   位置2   位置3
位置0 [ 1.00   0.00   0.00   0.00 ]
位置1 [ 0.35   0.65   0.00   0.00 ]
位置2 [ 0.20   0.30   0.50   0.00 ]
位置3 [ 0.10   0.15   0.45   0.30 ]
      └────── 只能看自己和左边 ──────┘
```

（数值是**示意**，只为说明形状与因果性。）

> **易错点提醒**：掩码要加在 softmax **之前**的分数上（加 $-\infty$），而不是加在 softmax **之后**的权重上（乘 0）。后者在数值上容易出 `0 × inf = NaN` 的问题。

### 4.5 多头：一次开好几桌会

单个注意力头只能学一种"关注模式"。**多头注意力**把 $D$ 维拆成 $H$ 份，每份 $d_{head} = D/H$ 维，各自独立做一遍注意力，最后拼回来再过一层线性变换：

- 不同的头可能学出不同分工：一个头盯语法邻接，一个头盯远距离指代，一个头盯标点；
- 拼回 $D$ 维后再乘 $W_O$，让各头的信息重新融合。

形状上就是：`(B, T, D)` → 拆成 `(B, H, T, d_head)` → 注意力 → 拼回 `(B, T, D)`。

### 4.6 为什么要除以 $\sqrt{d_{head}}$

$QK^\top$ 是内积。当维度变大时，$q$ 和 $k$ 的内积**方差会随维度线性增长**，数值尺度越来越大。经过 softmax 后，分布会变得极度尖锐（几乎是一个 1、其余都是 0），梯度几乎为 0，训练直接卡死。

除以 $\sqrt{d_{head}}$ 把尺度拉回正常范围，让 softmax 既不"太平"（什么权重都一样，学不到东西）也不"太尖"（学不到东西）。这叫**缩放点积注意力**里那个"scaled"。

### 4.7 位置信息：告诉模型"谁在前谁在后"

**注意力本身是分不清顺序的**——把输入的两个词对调，注意力算出来的东西跟着对调，但"词序"这件事就丢了。所以必须**显式**把位置信息加进模型。

本作业用 **RoPE（Rotary Position Embedding，Su 等，2021）**：

- 做法：把 $q$、$k$ 想象成平面上的箭头，**按各自的位置旋转一个角度**（位置越靠后，角度越大），再算它们的点积；
- 妙处：两个箭头旋转后点积的大小，只取决于**它们的相对距离**。这正好符合语言规律——"谁在谁前面"比"具体是第几个"更重要；
- 细节：RoPE **只作用于 Q 和 K，不作用于 V**（V 是要被取走的内容，旋转它没有语义收益，还会打乱数值）；
- 实现上：sin/cos 值是固定的，**不需要训练**，作为 buffer 预先算好。

对比一下其他方案：

| 方案 | 思路 | 特点 |
| --- | --- | --- |
| 正弦绝对位置编码 | 用不同频率的正弦波给每个绝对位置打标 | 原论文方案，可外推到更长序列 |
| 可学习绝对位置嵌入 | 每个位置存一个可学向量，和词嵌入相加 | 简单，但超出训练长度就失效 |
| RoPE | 旋转 Q/K，编码相对距离 | 效果与外推能力都好，本作业采用 |

### 4.8 前馈网络：SwiGLU

注意力做完"信息交换"之后，每个位置还需要一次**独立的思考**。这就是 FFN（Feed-Forward Network）：

- 它是**逐位置**的：位置 0 的 FFN 不会看到位置 1 的内容；
- 它**不改变序列长度**，只改变特征维度：$D \to d_{ff} \to D$（先"扩张"再"压回"）；
- 本作业用 **SwiGLU**（Llama 3 采用的形式）：

$$
\text{FFN}(x) = W_2\big(\text{SiLU}(W_1 x) \odot (W_3 x)\big)
$$

其中 $\odot$ 是**逐元素相乘**，SiLU 是激活函数。直观理解：一条支路算"门控信号"，另一条支路算"内容"，逐元素相乘相当于**用门控信号给内容逐通道调音量**——这比单纯的 ReLU 表达力更强。

> 类比：注意力是"开会时听谁发言"，FFN 是"散会后各自写心得"。会议是全场共享的，心得是个人的。

### 4.9 残差连接：给梯度修一条高速公路

`y = x + f(x)` 里的那个加法，就是残差连接。作用有三个：

1. **梯度高速公路**：反向传播时，梯度可以沿着"加号"这条直路原封不动地传回最底层，不必逐层穿过 f。层数越深，这条路越重要；
2. **保护原始信息**：子层的输出被理解成"**在原有内容上的修改**"，而不是"新的完整内容"。模型学起来更轻松；
3. **让深层网络可训**：没有残差时，几十层几乎训不动；有了它，梯度能畅通。

> 类比：原画 + 批注。批注可以很厉害，但原画永远还在，撕掉批注也不影响原画。

### 4.10 层与层的分工

堆叠 $N$ 层之后，每层大致分工如下（这是经验总结，不是硬性规定）：

- **靠前的层**：更关注字面、局部语法——"这里是个名词"、"这个标点是逗号"；
- **靠后的层**：更关注结构与语义——"这个 'it' 指的是前面那只狐狸"、"这句话在提问"。

每层内部也是同样的模式：**注意力做全局信息交换，FFN 做局部加工**。

### 4.11 注意力权重能看出什么

训练好的模型里，注意力权重图往往相当可读：某个代词的注意力会集中指向它指代的名词，某些词会吸引大量关注。这提供了一种"粗粒度地观察模型在想什么"的窗口。

需要注意的是：**注意力权重高 ≠ 这就是模型的因果解释**。相关性和因果性是两回事，这也是 Transformer 可解释性研究的长期争议点。

## 5. 输出层：向量 → 下一个词的概率

### 5.1 最终归一化 + 输出投影

走完 $N$ 层 Block 后，我们手上是 `(B, T, D)` 的向量序列。pre-norm 结构下，最后一层还需要做一次**最终归一化**（否则送进 LM head 的数值尺度可能失控），然后过一层线性变换（LM head，也叫输出嵌入）：

$$
\text{logits} = \text{Norm}(z) \, W^\top, \quad W \in \mathbb{R}^{V \times D}
$$

- 输入：`(B, T, D)`
- 输出：`(B, T, V)` 的 **logits**——每个位置都对全词表给出一组**未归一化的分数**。

### 5.2 logits → 概率

$$
\text{softmax}(\text{logits})_i = \frac{e^{\text{logits}_i}}{\sum_j e^{\text{logits}_j}}
$$

得到 `(B, T, V)` 的概率分布。对序列里第 $i$ 个位置，这个分布就是 $P(x_{i+1} \mid x_{1:i})$。

> **数值稳定小技巧**（讲义 3.4.4 节特别提到）：softmax 对"所有输入同时加上一个常数"是不敏感的。实现时先减去每行最大值再算 exp，就能避免 $e^{大数}$ 溢出成 inf、进而算出 NaN。

### 5.3 训练：交叉熵损失

训练时，把分布里"真实下一个词"的那个概率取出来算对数损失，再对所有位置求平均：

$$
\mathcal{L} = -\frac{1}{T}\sum_{i=1}^{T} \log P(x_{i+1} \mid x_{1:i})
$$

直觉：**模型给正确答案分配的概率越高，损失越小。** 如果模型自信地猜错了，损失会非常大——这会自动"惩罚"过度自信。

### 5.4 困惑度（Perplexity）

交叉熵适合训练，但不够直观。困惑度把它翻译成一句人话：

$$
\text{perplexity} = \exp\left(\sum \ell\right)
$$

**含义**：如果模型每次都在 V 个词里"随机猜"，困惑度就是 V；模型越好，这个数越接近 1。

- 困惑度 1 = 完美预测
- 困惑度 100 = 平均要试 100 次才猜中
- 同一个模型，在同一个数据集上，困惑度是可比的；但**跨 tokenizer 不可比**（词表不同、切分粒度不同，数字没有可比性）

困惑度是作业中报告的主要评估指标（要提交到 TinyStories 和 OpenWebText 的排行榜）。

### 5.5 推理：自回归生成循环

训练时是"teacher forcing"——每个位置的标签都是真实数据，一次算完全序列。生成时没有标签，只能**一步一步来**：

```text
1. 输入 prompt，得到最后一个位置的分布
2. 采样/贪心选出一个 token
3. 把它接到序列末尾
4. 重新跑一遍模型（只算新增那一位，见 KV cache）
5. 回到第 1 步，直到生成足够长度或遇到停止标记
```

**这就是"自回归"（autoregressive）**：一次生成一个词，用生成的词再生成下一个。

### 5.6 怎么"选"下一个词

| 策略 | 做法 | 特点 |
| --- | --- | --- |
| Greedy（贪心） | 永远选概率最大的 | 稳定但单调，容易重复 |
| 温度采样 | 除以温度 $\tau$ 再 softmax，$\tau<1$ 更尖、$\tau>1$ 更平 | $\tau$ 越大越发散 |
| Top-p（Nucleus） | 只在累积概率达到 $p$ 的最小候选集合里采样 | 兼顾多样性与合理性 |

讲义 5.x 节还提到 top-k 等变体，核心思想一致：**在"有可能"和"不跑偏"之间取平衡**。

## 6. 相关知识：位置信息、残差连接、训练与推理要点

### 6.1 位置信息为什么必须显式加

再强调一遍这个反直觉的点：把一句话的词序整体打乱，**纯注意力算出来的结果只是跟着一起打乱**——它本身没有任何"顺序"的先验。加注意力只会让词与词之间交换信息，并不会告诉你谁先谁后。

所以位置编码不是锦上添花，而是**语言模型能理解语法的地基**。

### 6.2 残差连接与梯度流

梯度（"参数该往哪个方向调、调多少"）在反向传播中是从后往前传的。没有残差时，每一层都要对梯度做一次变换，多层叠加后：

- 梯度可能**指数级衰减**（消失）→ 学不动；
- 也可能**指数级放大**（爆炸）→ 训练发散。

残差连接提供了**一条不经过任何变换的直路**。这也是为什么现代 Transformer 几乎都保留残差，并且几乎都用 pre-norm（把归一化放在子层前，保证主干上的数值尺度稳定，残差加法不会把数值搞飞）。

### 6.3 训练要点

| 主题 | 要点 |
| --- | --- |
| **优化器** | 用 AdamW：带自适应步长，且把权重衰减与梯度更新**解耦**（解耦后效果更好，也是当前主流） |
| **学习率调度** | 讲义用 **warmup + cosine annealing**：先从很小的学习率线性升到峰值（前 $T_w$ 步），再按余弦曲线平滑降到最小值。warmup 的作用是让训练最初几步别把随机初始化的模型带偏 |
| **梯度裁剪** | 梯度范数超过阈值就按比例缩小（clip）。它防的是"某一步冒出个巨大梯度把参数打飞"这种灾难 |
| **batch size** | 越大，梯度估计越准，但显存吃紧；讲义里有专门实验让你观察 batch size 对学习曲线的影响 |
| **初始化** | pre-norm 对初始化比较鲁棒，但仍要注意权重尺度（例如残差分支的初始化常常要小一点，让残差路径初期近似恒等映射） |
| **Checkpoint** | 要能**完整恢复训练**：模型参数 + 优化器状态（动量、二阶矩）+ 迭代步数，缺一不可（只存模型参数的话，恢复后优化器从头学起，训练曲线会明显抖动） |
| **数据打包** | 把语料切成定长块（见 2.2），既省掉 padding，吞吐也高 |

### 6.4 推理要点

| 主题 | 要点 |
| --- | --- |
| **KV cache** | 生成时每加一个 token，若重算整条序列，代价是 $O(T^2)$。把已算过的 K、V 缓存起来，每步只算新 token 的部分，降到 $O(T)$ |
| **缓存与批处理** | 缓存占显存，batch 越大缓存越多，要和序列长度一起规划 |
| **评估** | 困惑度是主指标；生成质量靠人眼和采样参数辅助判断 |
| **训练/推理差异** | 训练时一次算 $T$ 个位置（并行、高吞吐）；推理时逐个生成（受限于内存带宽，单 token 延迟更重要） |
| **模型规模 vs 数据量** | 讲义里的 scaling law 部分会讨论：算力有限时，把预算花在"更大的模型"还是"更多/更干净的数据"上，是个需要实验回答的问题 |

### 6.5 常见误区速查

| 误区 | 纠正 |
| --- | --- |
| "注意力权重就是模型关注的解释" | 高权重只是相关性强弱，不等于因果解释 |
| "加位置编码就是给每个位置加个数" | RoPE 是**旋转** Q/K，作用在注意力内部，不是加到输入向量上 |
| "掩码加在 softmax 之后" | 应该加在 softmax **之前**（设 $-\infty$），否则有 `0×inf=NaN` 风险 |
| "词表越大模型越好" | 词表影响序列长度、嵌入层大小和困惑度的可比性，要一起权衡 |
| "困惑度能跨模型比较" | 只有在**同一 tokenizer、同一数据**下才可比 |
| "Transformer 会"理解"文本" | 它在做可预测性建模；是否等同于理解，是哲学问题，不是工程问题 |
| "训练好的模型一定能记住训练数据" | 大模型有记忆训练样本的能力，这也是隐私与数据泄漏问题的来源 |

## 7. 小结与自测

### 7.1 一页速查

```text
输入阶段：  文本 → BPE token → (B,T) 整数 ID（标签错位一位）
映射阶段：  ID → 查表 → (B,T,D) 向量
核心变换：  N × Block[ Norm → 因果多头注意力(带 RoPE) → 残差
                            Norm → SwiGLU FFN              → 残差 ]
输出层：    最终 Norm → LM head(D→V) → logits → softmax → 概率
训练：      交叉熵 + AdamW + warmup/cosine + 梯度裁剪 + checkpoint
推理：      自回归逐 token 生成（温度/top-p）+ KV cache
评估：      困惑度 = exp(平均交叉熵)
```
