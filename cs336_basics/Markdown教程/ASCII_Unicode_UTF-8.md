## 一、什么是 ASCII

ASCII（American Standard Code for Information Interchange，美国信息交换标准代码）是计算机发展早期制定的一套字符编码标准，于 1963 年正式发布。

### 1. 编码方式

ASCII 使用 **7 位二进制数**（7 个 bit）来表示一个字符，因此一共可以表示 $2^7 = 128$ 个不同的字符。在实际存储时，通常占用 1 个字节（8 位），最高位恒为 0。

### 2. 字符范围

128 个字符包括：

| 范围 | 含义 |
| --- | --- |
| 0 ~ 31 | 控制字符（如换行符 `\n`、回车符 `\r`、制表符 `\t` 等） |
| 32 | 空格 |
| 33 ~ 126 | 可见字符（英文字母 A-Z、a-z，数字 0-9，标点符号等） |
| 127 | 删除控制符 DEL |

### 3. 举例

- `'A'` 的 ASCII 码是 65，二进制写作 `0100 0001`
- `'a'` 的 ASCII 码是 97，二进制写作 `0110 0001`
- `'0'` 的 ASCII 码是 48，二进制写作 `0011 0000`

### 4. 局限性

ASCII 只能表示英文及相关符号，无法表示中文、日文、阿拉伯文、表情符号等世界上其他语言的文字。因此它只适用于英语世界。

## 二、什么是 Unicode

随着计算机在全球普及，各国都需要在计算机中表示自己的文字。如果每个国家都定义一套自己的编码（比如中国的 GBK、日本的 Shift-JIS），就会出现同一个二进制数值在不同编码下代表不同字符的混乱局面，导致跨语言、跨平台的文本交换变得极其困难。

为了解决这个问题，**Unicode（统一码）** 应运而生。它是一个国际标准（对应 ISO/IEC 10646），目标很简单：为世界上所有字符（包括文字、符号、emoji、甚至已消亡的文字）分配一个唯一的编号。

### 1. 码点（Code Point）

Unicode 为每个字符分配的唯一编号称为**码点**，通常写成 `U+XXXX` 的形式，其中 XXXX 是十六进制数。例如：

- `'A'` 的码点是 `U+0041`
- `'中'` 的码点是 `U+4E2D`
- `'😀'`（grinning face）的码点是 `U+1F600`

### 2. 码点空间

Unicode 的码点范围是 `U+0000 ~ U+10FFFF`，共 **17 个平面（Plane）**，每个平面包含 65536 个码点，总计可表示超过 111 万个字符。

- **第 0 号平面**（`U+0000 ~ U+FFFF`）称为基本多文种平面（BMP），收录了最常用的字符，包括绝大多数汉字和常用符号；
- **第 1 号平面**（`U+10000 ~ U+1FFFF`）等辅助平面则收录了罕见汉字、emoji、古代文字等。

### 3. 重要认识：Unicode 本身不是编码方式

Unicode 只规定"每个字符对应哪个编号（码点）"，它并不直接规定这些编号在计算机内存或文件中如何用字节存储。把码点转换成字节序列的具体方案，就是 UTF-8、UTF-16、UTF-32 等**编码方式（encoding）**。

> 可以把 Unicode 理解为一本"字符编号字典"，而 UTF-8 等则是"把字典编号写成字节"的规则。

## 三、ASCII 与 Unicode 的映射关系

ASCII 与 Unicode 之间存在着非常直接、优雅的映射关系：

### 1. Unicode 的前 128 个码点与 ASCII 完全一致

- ASCII 字符 `'A'`（数值 65）在 Unicode 中的码点就是 `U+0041`
- ASCII 字符 `'~'`（数值 126）在 Unicode 中的码点是 `U+007E`

也就是说，**ASCII 字符集被完整地嵌入到了 Unicode 的前 128 个码位中**，一个比特都没变。

### 2. 历史原因

Unicode 的设计者有意保持这种兼容性，使得原本用 ASCII 编码的英文文本可以平滑地过渡到 Unicode 世界，旧系统也不会失效。

### 3. 实践意义

正因为存在这种映射关系，纯英文文本用 UTF-8 编码后，其字节序列与 ASCII 编码完全相同（详见第五节）。这也是 UTF-8 能够成为互联网主流编码的关键原因之一。

## 四、UTF-8、UTF-16、UTF-32 的对比

Unicode 码点要存储到计算机中，需要用字节表示，由此产生了多种编码方式。最常见的三种是 UTF-8、UTF-16 和 UTF-32。

### 1. UTF-32

- **编码方式**：每个码点固定用 4 个字节（32 位）存储。
- **优点**：
  - 最简单直接，码点与字节一一对应，不需要任何转换计算；
  - 随机访问第 n 个字符非常快（直接偏移 4n 个字节即可）。
- **缺点**：
  - 太浪费空间。存储一个 ASCII 字符也要 4 个字节，英文本文件体积膨胀 4 倍；
  - 与既有 ASCII 系统不兼容；
  - 还涉及字节序（大端/小端）问题。
- **适用场景**：内部处理逻辑简单、不在乎空间的特定系统。

### 2. UTF-16

- **编码方式**：BMP 内的码点（`U+0000 ~ U+FFFF`）用 2 个字节存储；辅助平面的码点（`U+10000` 以上，如部分 emoji、罕见汉字）需要 4 个字节存储，采用**代理对（Surrogate Pair）**机制，即用两个 2 字节的代码单元组合表示一个字符。
- **优点**：
  - 对常用字符（BMP 内）只需 2 字节，比 UTF-32 省一半空间；
  - BMP 范围内随机访问字符相对方便。
- **缺点**：
  - 空间仍然不够节省，英文字符也要 2 字节；
  - 存在变长问题（2 字节或 4 字节），且引入了复杂的代理对概念，编程处理容易出错；
  - 同样存在字节序（大端/小端）问题；
  - 与 ASCII 不兼容。
- **适用场景**：Windows 操作系统内部、Java 语言默认字符编码等历史原因大量使用的环境。

### 3. UTF-8

- **编码方式**：**变长编码**，一个字符占用 1 ~ 4 个字节，根据码点大小使用不同长度的字节序列。
- **优点**：
  - 对 ASCII 字符完全兼容：ASCII 文本在 UTF-8 中就是其本身，旧软件无需修改即可处理；
  - 空间效率高：英文文本与 ASCII 一样只占 1 字节/字符，中文通常占 3 字节/字符，远小于 UTF-16/UTF-32；
  - 没有字节序问题：UTF-8 按字节为单位解释，不存在大端/小端之分；
  - 自同步性强：字节序列本身能标明字符边界，即使中间损坏也容易定位下一个字符；
  - 容错性好，已被互联网全面采用，事实上的通用标准。
- **缺点**：
  - 变长编码，某些语言（如中文、日文）的文本比 UTF-16 占用空间略大（中文 3 字节 vs 2 字节）；
  - 随机访问第 n 个字符需要从头扫描，无法直接按索引定位。
- **适用场景**：互联网网页、Linux/macOS 系统文本、现代编程语言源码、JSON/HTML/XML 等数据格式的默认编码。

### 4. 一句话总结

| 编码方式 | 字节长度 | 核心特点 |
| --- | --- | --- |
| UTF-32 | 定长 4 字节 | 简单但浪费 |
| UTF-16 | 定长 2 字节为主、辅助平面 4 字节 | 折中但有代理对复杂性 |
| UTF-8 | 变长 1~4 字节 | 兼容 ASCII、省空间、无字节序问题，最流行 |

## 五、UTF-8 编码原理详解

UTF-8 的核心思想是：**根据 Unicode 码点的大小，选用 1 到 4 个字节进行编码，并且让字节的前几位"标志位"标明该字符占几个字节、以及每个字节是首字节还是后续字节。**

### 1. 编码规则总览

| 码点范围（十六进制） | 字节数 | 字节序列（二进制模板） |
| --- | --- | --- |
| `U+0000 ~ U+007F` | 1 字节 | `0xxxxxxx` |
| `U+0080 ~ U+07FF` | 2 字节 | `110xxxxx 10xxxxxx` |
| `U+0800 ~ U+FFFF` | 3 字节 | `1110xxxx 10xxxxxx 10xxxxxx` |
| `U+10000 ~ U+10FFFF` | 4 字节 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

其中 `x` 表示用来填充实际码点比特的位置。

### 2. 规则解读

**(1) 首字节标志位**

- `0` 开头：单字节字符，说明这是 1 字节编码（兼容 ASCII）
- `110` 开头：2 字节编码的首字节
- `1110` 开头：3 字节编码的首字节
- `11110` 开头：4 字节编码的首字节

**(2) 后续字节标志位**

每个后续字节固定以 `10` 开头，其余 6 位承载数据。

**(3) 数据比特数**

- 1 字节编码可容纳 7 位数据（$2^7 = 128$，正好对应 ASCII）
- 2 字节编码可容纳 5 + 6 = 11 位数据（覆盖到 `U+07FF`）
- 3 字节编码可容纳 4 + 6 + 6 = 16 位数据（覆盖整个 BMP，即绝大多数常用字符，包括全部常用汉字）
- 4 字节编码可容纳 3 + 6 + 6 + 6 = 21 位数据（覆盖全部 Unicode 码点空间）

### 3. 编码步骤示例

以汉字 **"中"** 为例，它的 Unicode 码点是 `U+4E2D`。

**第 1 步：查表确定字节数。**

`U+4E2D` 落在 `U+0800 ~ U+FFFF` 区间，需要 3 字节编码。

**第 2 步：将码点转为二进制。**

```
4E2D（十六进制）= 0100 1110 0010 1101（二进制），共 16 位
```

**第 3 步：按模板填充比特。**

3 字节模板为：`1110xxxx 10xxxxxx 10xxxxxx`，可用的数据位是 4 + 6 + 6 = 16 位，刚好放下码点。从高位到低位依次填入：

```
码点：   0100 1110 0010 1101
分段：   0100 | 111000 | 101101
填入：
 1110[0100]  ->  1110 0100
 10[111000]  ->  1011 1000
 10[101101]  ->  1010 1101
```

**第 4 步：得到最终字节序列。**

"中"的 UTF-8 编码为 **`E4 B8 AD`**（十六进制），二进制为 `1110 0100 1011 1000 1010 1101`，共 3 个字节。

再看一个 ASCII 字符 `'A'`（码点 `U+0041`）：落在 `U+0000 ~ U+007F` 区间，用 1 字节编码。`0x41 = 0100 0001`，直接写作 `0100 0001`。所以 `'A'` 的 UTF-8 编码就是 `0x41`，与 ASCII 完全一致。

### 4. 解码过程（如何从字节还原字符）

解码是编码的逆过程：

1. 读一个字节：
   - 若以 `0` 开头：这是单字节 ASCII 字符，直接取后 7 位；
   - 若以 `110` 开头：这是 2 字节字符，继续读 1 个后续字节；
   - 若以 `1110` 开头：这是 3 字节字符，继续读 2 个后续字节；
   - 若以 `11110` 开头：这是 4 字节字符，继续读 3 个后续字节。
2. 后续字节必须以 `10` 开头，去掉标志位后按顺序拼接数据位；
3. 把拼好的二进制数转成十六进制，即得到 Unicode 码点，再通过 Unicode 码点表找到对应字符。

正是因为有这些醒目的标志位，UTF-8 具备**自同步**特性：即使从一个字节序列的中间开始读，也能很快判断当前字节是首字节还是后续字节，从而找到字符边界。

### 5. 为什么 UTF-8 是互联网的胜利者

- **兼容性**：所有 ASCII 文本天然就是合法的 UTF-8 文本，几十年来积累的英文系统、协议、文件格式几乎零成本迁移；
- **空间**：英文内容不膨胀，多语言内容也有合理的体积；
- **简洁**：没有字节序问题，不需要 BOM（字节顺序标记）也能正确解析；
- **健壮**：标志位设计让损坏的数据不至于扩散，便于错误检测。

今天，超过 95% 的网页使用 UTF-8 编码，它已经是文本数据的默认标准。

## 六、小结

1. **ASCII** 是最早的字符编码，用 7 位表示 128 个英文字符，简单但只能处理英文。
2. **Unicode** 给世界上所有字符分配了唯一编号（码点，`U+XXXX` 形式），解决了"一码多义"的混乱，但它本身只定义编号，不定义字节存储方式。
3. **ASCII 被完整嵌入 Unicode 前 128 个码点**，二者一一对应，这为 UTF-8 的兼容性奠定了基础。
4. **UTF-32、UTF-16、UTF-8** 是把 Unicode 码点写成字节的三种方案：
   - UTF-32 定长 4 字节，简单但浪费；
   - UTF-16 以 2 字节为主，辅助平面用代理对，省空间但复杂；
   - UTF-8 变长 1~4 字节，兼容 ASCII、省空间、无字节序问题，是当今绝对主流的编码方式。
5. **UTF-8** 通过精心设计的首字节标志位（`0`、`110`、`1110`、`11110`）和后续字节标志位（`10`），让 1~4 字节的变长编码既能覆盖全部 Unicode 字符，又保持了对 ASCII 的完全兼容和强大的自同步能力。

理解了 ASCII、Unicode 与 UTF-8 的关系，就理解了现代计算机处理文本的基石。下次当你打开一个网页、编辑一个文本文件时，你可以自豪地知道：幕后正是这些编码规则在默默地工作。
